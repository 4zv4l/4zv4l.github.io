Production Incident Triage & Systems Assessment

1. Context

This assessment is a live, practical technical evaluation of your sysadmin abilities.

There are no environments to build, no hypervisors to configure, and zero local software installations required.

You will be given root access to an ephemeral Linux instance running directly in your web browser. You will walk us through your troubleshooting process in real time as you resolve active alerts on the system.

2. Environment & Access

  • Platform: In-browser ephemeral Alpine Linux terminal (WASM/x86).
  • Access Level: Full root privileges.
  • Session Duration: Approximately 20–30 minutes.
  • Format: Live screen-share. You are expected to vocalize your thoughts and explain your reasoning as you run commands.

3. Incident 1: Disk Activity & Task Scheduling

3.1. Scenario

The monitoring system has triggered a recurring disk activity alert. A log file located at /var/log/deployment was recently created and is receiving continuous automated writes.

3.2. Requirements

  1. Identify which process, file, or background scheduler is responsible for appending to /var/log/deployment.
  2. Inspect the script/executable executing the task and perform an operational and security audit. Audit the file and remediate any security issues identified.
  3. Reconfigure the scheduler so that the task runs once every 5 minutes instead of its current frequency.
  4. Verify that the changes took effect without breaking execution.

4. Incident 2: Unauthorized Network Listener

4.1. Scenario

A pentester running nmap found an unexpected listening socket bound to TCP port 444.

4.2. Requirements

  1. Verify whether port 444 is currently open and bound on this host using native command-line utilities.
  2. Determine the process name, binary path, and Process ID (PID) associated with this listening socket.
  3. Terminate the offending process.
  4. Verify that the socket has been fully released.

5. Incident 3: Authentication Audit & Network Path Analysis

5.1. Scenario

Multiple failed authentication events were recorded on this host. An audit log is available at /var/log/auth_audit.log.

5.2. Requirements

  1. Construct a one-liner command pipeline (so without opening a text editor) to:
    • Filter only the failed authentication attempts.
    • Extract the source IP addresses.
    • Count, and display the occurrences ranked from highest to lowest frequency to isolate the primary offending IP.
  2. Networking Assessment (Verbal):
    • Explain/categorize the IP ranges observed in the log file from a network architecture perspective.
    • Explain how an external, internet-originating IP address could reach this host if the host is situated on an internal LAN behind a NAT.
